# Переключение разрешения внутри игры

На итоговых сборках ARMHF и AArch64 проверен цикл 800×600 → 1024×768 → 800×600
через графические настройки и применение выбранного режима в одном процессе
игры с загруженной кампанией. Исполняемый файл не перезапускается вручную,
сохранение повторно не загружается, персонаж и кампания сохраняются.

Применение нового разрешения пересоздаёт контролы и их размеры. В 1024×768
общая адаптация к минимальному кадру отключается. При возврате в 800×600
она включается снова. Приведённые ниже кадры сняты до исправления
центрирования оборудования в 1024×768; актуальная проверка —
[центрирование в обоих разрешениях](../centered-1024/README.md).

При проверке обнаружена и исправлена ошибка программного рендерера:
масштабируемые мобильные контролы при переходе в 1024×768 попадали в старый
CPU-путь отрисовки и давали обрезку и повтор панели у края экрана. Теперь
SDL software сохраняет преобразования текстур для мобильного интерфейса
Anbernic при любом разрешении. Отрисовка остаётся программной: это не
аппаратное ускорение и не доказательство работы GPU физической приставки.

Настройка «Мобильный интерфейс» независима от разрешения. Переключение
в 1024×768 сохраняет её значение; для обычного интерфейса выберите «Нет».

Кадры получены из SDL без изменения размера. Тесты выполняются под QEMU
с SDL dummy. Отчёты содержат историю фактических режимов, код завершения
и SHA256 бинарников. Опубликованный релиз пока не обновлён.

На ARMHF проведено сравнение с [отдельным запуском сразу в 1024×768](armhf-fresh-ship-1024.png).
Два статичных участка интерфейса совпали по пикселям; статичный участок
после возврата в 800×600 также совпал с исходным кадром. Это проверка
выбранных областей, а не побитовое сравнение всего экрана: корабль и фон
анимируются. [Результат сравнения](armhf-layout-comparison.json).
