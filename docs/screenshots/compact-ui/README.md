# Сравнение вариантов адаптации интерфейса для Anbernic

После сравнения выбран минимум **800×600**. Снимки ниже сохраняют результаты предыдущего прототипа; 640×480 больше не предлагается как поддерживаемый режим. В текущем коде Anbernic для 800×600 достаточно `VideoMode=800,600`; экспериментальный ключ не требуется. При выборе меньшего разрешения используется 800×600. Режим `--renderer=software` в 800×600 тоже использует программный текстурный путь SDL для масштабирования интерфейса.

## 800×600

Сохранить две колонки на экране создания персонажа и оригинальное оформление меню. Вписать интерфейс в экран без обрезания. Масштабировать HUD отдельно от карты космоса, которая отрисовывается непосредственно в 800×600.

## 640×480

Вписывание оригинального интерфейса устраняет обрезание, но текст становится мелким. Для дальнейшей адаптации рекомендуются вкладки «Персонаж», «Сложность» и «Снаряжение» с переключением L/R, текст размером хотя бы 12–14 экранных пикселей, увеличенные основные кнопки и разворачиваемые подсказки. Это предложение следующего этапа; вкладки пока не реализованы и не показаны на снимках.

## Рабочий пробный вариант

Снимки ниже получены из игры, а не из графического редактора. В этом варианте меню и создание персонажа используют оригинальные координаты 1024×768 с масштабированием элементов при отрисовке в кадр 640×480 (0,625) или 800×600 (0,78125). В космосе масштабируется HUD; карта сохраняет координаты и разрешение текущего кадра. Полноразмерного кадра игры 1024×768 с последующим уменьшением здесь нет.

- 640×480: [меню](640x480/menu.png), [создание персонажа](640x480/character.png), [космос](640x480/space.png).
- 800×600: [меню](800x600/menu.png), [создание персонажа](800x600/character.png), [космос](800x600/space.png).

Для запуска показанной прежней экспериментальной сборки требовались `--experimental-low-res --renderer=sdl --windowed` и `VideoMode=640,480` либо `VideoMode=800,600` в CFG.TXT. По умолчанию режим выключен. В этой тестовой среде SDL не предоставляет ускорение и автоматически использует программный рендерер. Для масштабирования экспериментального интерфейса используется текстурный путь SDL, который тоже растеризуется на CPU. Принудительный `--renderer=software` сохраняет старый путь OKGF; адаптация для него ещё не реализована.

Проверка: ARMHF под QEMU с лицензионными ресурсами 2.1.2500. Для каждого разрешения сняты меню и создание персонажа, затем в отдельном прогоне загружено прежнее автосохранение и выполнен вылет; космос отрисовывался 20 секунд. Новая кампания целиком, экранная клавиатура при этих разрешениях, остальные экраны и физические приставки не проверялись. Результаты и хеш единой сборки сохранены в validation.json. PNG преобразованы из BMP без изменения размера.

Это ограниченный прототип для сравнения, не законченная адаптация всех экранов. Публичные релизные пакеты не обновлены. Актуальная проверка выбранного минимума — в [minimum-800-validation.json](minimum-800-validation.json).
