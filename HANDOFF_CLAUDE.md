## Что изменено в коде

От предыдущего публичного релиза на базе `628ca3a` накоплены этапы 4–8.

1. **Этап 4, `14cd33f`:** в режиме ограничения FPS готовый кадр ожидает срока
   показа через presentation pacer и `Sleep(0)`. Убрана лишняя очистка окна,
   когда копируемый кадр полностью покрывает вывод. При полях очистка остаётся.
   Основные файлы: `source/GR_Main.pas`, `platform/GameGraphics.pas`.
2. **Этап 5, `7bc72e8`:** непрозрачные статические RGB565-текстуры используют
   `SDL_BLENDMODE_NONE`, если alpha всех вершин равна 255. Render targets
   исключены, полупрозрачные и прочие текстуры сохраняют смешивание.
3. **Этап 6, `c1b4a8e`:** заполненный прямоугольник рисуется двумя треугольниками
   вместо четырёх с вырожденными хвостовыми гранями. Целочисленные непрозрачные
   осевые прямоугольники одного цвета используют `SDL_RenderFillRect`.
4. **Этап 7, `875e743`:** задаётся обычный SDL hint `SDL_RENDER_BATCHING=1`.
   Явный `SDL_RENDER_DRIVER` иначе отключает очередь в тестированной SDL.
   На accelerated renderer масштабированные полностью непрозрачные точки
   объединяются в одну геометрию из прежних пиксельных блоков. Software,
   масштаб 1×1 и смешанная alpha используют прежний путь. Буфер переиспользуется.
   Пользовательский env `SDL_RENDER_BATCHING=0` сохраняет приоритет над hint.
5. **Этап 8, `c605e88`:** только `source/scene/GI_SpaceImg.pas`:
   при готовой текстуре удалён предварительный `LoadFrameGi`; индекс кадра
   вычисляется один раз вместо четырёх, текстура запрашивается один раз вместо
   двух. При отсутствии текстуры декодирование выполняет существующий
   `GetOrCreateFrameSurface`. Origin читается после создания текстуры.
   Путь через `ScreenRenderBuffer` сохраняет загрузку кадра.

Резервный лимит FPS уже был изменён ранее на 60, если частоту экрана определить
не удалось. Не возвращать произвольные 50 Гц. VSync, отключение лимита и
фактическая частота дисплея имеют собственные пути; смотреть код pacer.

## Измерения: что подтверждено, а что нет

Главный источник: `docs/performance/README.md`. Машинные отчёты рядом:

- `presentation-fps-results.json`;
- `opaque-texture-fps-results.json`;
- `solid-rectangle-results.json`;
- `gpu-point-batching-results.json`;
- `space-gai-cache-results.json`.

Облачный QEMU/SDL software не измеряет GPU приставки. Native Mesa offscreen
также не является замером Anbernic. Не обещать по этим данным прирост на всех
физических устройствах.

Для этапа 7 native GLES2 дал +3,40% в сценарии явного драйвера и +2,00% при
масштабировании 1024×768 → 640×480. Во втором сценарии очередь включена обеим
версиям. Разные строки не сравнивать между собой: отличаются режимы вывода.
Изменение времени внутри `RenderGeometry` может означать перенос исполнения
к flush, поэтому оно не равно сокращению времени всего кадра.

Для принятого этапа 8 относительно `875e743`:

| Сценарий | Медиана FPS до → после | Разница |
| --- | --- | --- |
| Native GLES2, 1024×768 | 93,10 → 93,16 | +0,06% |
| Native GLES2, выход 640×480 | 244,18 → 245,81 | +0,67% |
| ARMHF, QEMU software, лимит FPS | 58,75 → 59,02 | +0,46% |

**Устойчивый прирост среднего FPS для этапа 8 не подтверждён.** Сокращение
загрузок кадра подтверждено проверкой состояния декодера и совпадением пикселей.
Сравнительного игрового FPS AArch64 для принятого этапа 8 нет.
Свежие релизные ELF проверены запуском; их FPS отдельно не сравнивался.
Не смешивать их хеши с более ранними бинарниками замеров того же исходного кода.

Метод измерений: ABBA, два 20-секундных прогона каждой версии, одно
автосохранение, один закреплённый CPU. GPU-тесты без VSync и лимита; в режиме
640×480 заданы обеим версиям batching=1 и LP_NUM_THREADS=1. В этих замерах
`BGImage` отсутствовал в CFG и был False.

## Отклонённые идеи — не восстанавливать без новых доказательств

- Поиск alpha в ARGB-пикселях для расширения режима NONE не показал пользы:
  около −0,02% в контрольном измерении. Был удалён.
- Кэш границ всех GI-кадров фона дал −1,50% FPS при `BGImage=True`.
- Прямое чтение границ несжатого GI с кэшем сжатых кадров дало +1,14% с фоном
  при пересекающихся диапазонах и −0,52% без фона. Также удалён.
- **В c605e88 нет кэша границ и новых полей в `TCGaiEC`; `GI_StarField.pas`
  и `EC_CacheGAI.pas` сохранены в прежнем виде.**

В `.local/performance/stage8/` много артефактов отклонённых вариантов с именами
`final`, `v2`, `v3`. Само имя не подтверждает, что вариант принят. Для принятого
варианта использовать `space-gai-cache-results.json`, `space-image-only/`,
`cache-validation-objects.json`, `build-provenance-objects.json` и
`objects-final-space-*`. Отчёт фиксирует точные хеши.

## Регрессионные проверки

`tools/tests/space_image_cache.pas` использует синтетический GAI, без лицензируемых
ресурсов. Проверяет обычный и сжатый RGB565, пустой кадр, перестановку кадров,
ненулевой origin, scissor, очистку текстур и reset. Для исходной версии передать
`--baseline`. Объекты проверяют исчезновение повторной загрузки; фон — сохранение
прежнего поведения. Пройдены 10 процессов: обе версии на трёх архитектурах
через software, затем обе версии на native OpenGL и OpenGL ES 2. Пиксели совпали.

Для предыдущих этапов есть `point_blocks.pas`, `solid_rectangle.pas`,
`opaque_texture.pas`, `presentation_coverage.pas`, `texture_state.pas`,
`ui_tile_seams.pas`, `clip_transform.pas`, `frame_pacing.pas`.
`force_accelerated_info.c` — тестовый preload, заставляющий код пройти ветку
пакета точек над настоящим SDL software. Он не моделирует физический GPU.

Не проверены: реальные приставки/GPU, звук, контроллеры, длительная игра,
тяжёлые бои и широкий набор кампаний. Функциональный smoke ≠ сравнение FPS.

Эти пути относятся к текущей машине. В новой среде `.local`, `/workspace/.srhd-env`
и `/workspace/shared` могут отсутствовать: сначала восстановить окружение.

В managed cloud читать применимые runtime-инструкции; текущий runtime-status
сообщил connected/running, но состояние сетевой политики unknown и не объявил
готовые credential bindings. Не выводить секреты и не считать это подтверждением
готовности авторизации. Startup-снимок `/etc/codex/network-policy.json`
задаёт restricted HTTP policy; перед новой сетевой работой проверять актуальный
доступ и сохранять настройки proxy. `gh` и git push успешно использовались
в этой сессии.

```bash
cd /workspace/SRHD_FPC_Anbernic
source /workspace/.srhd-env/activate.sh
python3 tools/build.py --target linux --release
```

- Clang/LLVM/lld 19: `/workspace/.srhd-env/root`.
- Нативный FPC: `.local/fpc/`.
- ARMHF: `/workspace/.srhd-env/fpc-armhf/compiler/ppcrossarm`, ARMV7/VFPV3/EABIHF,
  оптимизация релиза O2.
- AArch64: `/workspace/.srhd-env/fpc-arm64/compiler/ppcrossa64`, LLVM backend,
  параметры `-Clv17.0 -Aclang-llvm`.
- RTL: `/workspace/.srhd-env/fpc-{armhf,arm64}/rtl/units/{arm,aarch64}-linux`.
- SDK релиза: `/workspace/.srhd-env/release-sdk/{armhf,arm64}/root` — Ubuntu 20.04.
- Bin wrappers: соответствующие `release-sdk/<arch>/bin`.
- QEMU: `/workspace/.srhd-env/root/usr/bin/qemu-{arm,aarch64}`.
- SDL 2.32.4 собиралась только для линковки и headless-тестов; **не паковать её**.
  Реальная SDL ≥ 2.26.0, GPU-драйверы и glibc ≥ 2.29 берутся из прошивки.
- Paszlib компилировать отдельно в ObjFPC: прямое пересобирание этого пакета
  в Delphi mode приводит к ошибкам; использовать существующие build tools.

## Как продолжать оптимизацию

1. Брать базу c605e88 и свежие релизные ELF; проверить актуальность веток.
2. Профилировать настоящие затраты выбранной сцены, отдельно учитывать
   BGImage=False/True и ограниченный/неограниченный FPS.
3. Предпочитать изменение с проверяемым эффектом на время всего кадра.
   Не выдавать сокращение числа вызовов или synthetic throughput за прирост
   игрового FPS. Не менять качество ради неподтверждённой цифры.
4. Проверить пиксели, reset, alpha, scissor и нужные архитектуры; затем измерить
   относительно неизменяемой базы без параллельной нагрузки.
5. При новом запросе билда собрать обе архитектуры, проверить именно
   упакованные бинарники и сохранить формат пяти ZIP + SHA256SUMS.

Физического оборудования в этой сессии не было. Если нужен подтверждённый
прирост на приставках, необходимы сопоставимые аппаратные измерения.
